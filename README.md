# InterGate · AI API 智能中转网关(Python 版)

> **开发者**: 恣桐

> 在 Termux / 任何 Linux 上运行,统一管理多家 AI 服务商 API Key,提供负载均衡、失败自动切换、
> 限流、响应缓存、额度监控、模型同步,并附带一个 Web 控制台。

第三方 AI 应用(ChatBox、NextChat、Open WebUI、自定义脚本...)只需把 `base_url` 指向本网关,
即可共享这一批受管理的高可用 Key。

## 核心特性

- **多提供商接入** — openai / anthropic / google / azure / opencode / custom,统一适配
- **6 种负载均衡策略** — 轮询、加权轮询、优先级、最少连接、响应时间、智能
- **失败自动切换** — 连续失败自动冷却与恢复,单请求最多切换 3 个 Key;
  可选「禁用自动关闭 Key」: 失败/额度耗尽仅记录与告警, 不自动禁用(设置页开关, 即时生效)
- **模型列表同步** — 自动拉取各提供商模型,统一格式、能力推断
- **响应缓存** — 复用幂等 2xx 响应,降低重复请求成本(响应头 `x-relay-cache`)
- **多维限流** — IP / 全局 / Key RPM 限流,自适应 TPM(AIMD 动态调整)
- **额度与告警** — 每日配额、错误率监控、额度耗尽自动禁用,持续性告警按天去重
- **Key 安全管理** — AES-256-GCM 本地加密,明文不落盘、不写日志;管理台接口敏感字段一律脱敏
- **Web 控制台** — 仪表盘、Key 管理、模型、租户 Token、日志、设置(7 个子页签),6 套主题,中英双语,一键启停

## 安装

```bash
# 1. 进入项目
cd ~/工作目录/InterGate

# 2. 安装依赖(Python 3.10+)
pip install -r requirements.txt
# 或: pip install fastapi uvicorn httpx cryptography

# 3. 启动 / 停止
./run.sh              # 后台启动
./run.sh status       # 查看运行状态
./run.sh restart      # 重启(改配置/更新后)
./run.sh stop         # 停止
```
> 重复执行 `./run.sh` 不会报端口占用(自动检测已在运行)。若出现
> `Errno 98 address already in use`,说明端口被旧进程或其它程序占用,
> 先 `./run.sh stop`,确认端口释放后再启动。

## 使用

启动后:

| 服务 | 地址 | 说明 |
|---|---|---|
| 代理网关 | `http://0.0.0.0:51234` | OpenAI 兼容 API(`/v1/chat/completions` 等) |
| Web 控制台 | `http://0.0.0.0:51235` | 浏览器打开,管理 Key / 模型 / 日志 / 设置 |

1. 打开 Web 控制台 → 「Key 管理」→ 添加各提供商 API Key。
2. (可选)「模型」页点击「同步模型」拉取可用模型。
3. 第三方应用设置:
   ```
   base_url = http://<手机IP>:51234/v1
   api_key  = <网关 Key>(设置里配置了网关 Key 时才需要)
   ```

高级用法(请求头):

| 请求头 | 作用 |
|---|---|
| `x-relay-provider: openai` | 强制指定提供商 |
| `x-relay-key: 名称或ID` | 强制指定某个 Key |
| `x-relay-cache` | 缓存命中时网关返回该头 |

管理接口(需携带网关 Key):`/relay/stats` 运行统计、`/relay/report` 额度报表、`/relay/version` 版本、`/relay/cache` 缓存统计、`/relay/metrics` Prometheus 指标。

> **v1.1.3 起**:未配置网关 Key 时,上述管理接口一律返回 `401`(不再匿名放行);
> 代理接口 `/v1/*` 保持开放不受影响。租户 Token 只能代理调用,不能访问管理接口。
> 需要用监控脚本抓 `/relay/metrics` 的,请先在「设置 → 网关」配置主网关 Key。

## 安全说明

- API Key 使用 AES-256-GCM 加密存储,主密钥在 `data/.master_key`(权限 0600)。
- 网关默认不鉴权(局域网内均可调用代理接口);建议在「设置」中配置主网关 Key 后再暴露到局域网。
  配置后,调用网关需携带 `Authorization: Bearer <网关 Key>`,并支持按权限拆分的附加网关密钥。
- 网关管理接口(`/relay/stats`、`/relay/report`、`/relay/version`、`/relay/cache`、`/relay/metrics`)
  **必须**携带有效网关 Key:匿名请求与租户 Token 均被拒绝(401);健康检查 `/health`、`/healthz`、`/ping` 保持公开。
- 管理 API 中对敏感字段一律脱敏返回(仅保留首尾各 4 字符,长度 ≤12 整体打码),明文需通过
  `/api/settings/secret/{field}` 单独获取;回传脱敏值不会覆盖原配置。
- 配置导出文件中的密钥为**明文**(以便跨机器还原,AES 密文依赖本机主密钥),请妥善保管导出文件。
- Web 控制台:未设置管理台密码时仅本机(`127.0.0.1`)可访问;设置密码后局域网可访问。
  登录 token 24 小时有效,登录接口有失败限速(60 秒内 5 次失败即临时锁定)。
- 响应缓存按「租户 + 凭证 + 提供商」隔离,不同租户的相同提问不会命中同一份缓存。
- 生产环境请做好网络访问控制,遵守各 AI 服务商使用条款。

## 版本历史

### v1.1.3 (2026-10-31)

> 安全审计与缺陷修复版本。对整个代码库(约 8200 行 Python + 3240 行控制台)做了一轮
> 定向审计, 逐项复现并修复 15 个缺陷, 其中 4 个为 P0。所有修复均附带回归用例。

#### 新功能与界面
- **禁用自动关闭 Key(运行时开关)**: 新增设置项 `auto_disable_enabled`(默认开启, 保持原行为)。关闭后, 上游失败、认证失败、额度耗尽仅记录失败计数与告警, 不再自动将 Key 置为 ERROR/EXHAUSTED 或进入冷却; 手动停用 Key 不受影响。开关经共享 settings 注入 `KeyManager`/`QuotaMonitor`, 控制台修改即时生效, 无需重启。
- **设置页拆分为 7 个子页签**: 原 11 张卡片堆叠的单页拆分为「通用 / 网关 / 安全 / 缓存与限流 / 告警与日志 / 价格 / 数据与接入」, 页签位置记忆(localStorage), 所有卡片内容保留。
- **新增「墨海」「羊皮纸」主题**: 深邃蓝黑低刺激夜间主题与暖色护眼浅色主题, 主题总数 4 → 6(自动/浅色/深色/墨海/羊皮纸/液态玻璃), PWA 状态栏颜色分别适配。
- **全主题视觉细节打磨**: 文字选中色、键盘焦点态(`:focus-visible`)、细滚动条(webkit + Firefox)、卡片阴影过渡、按钮按压反馈。

#### 安全修复 (P0)

- **租户鉴权引用未定义变量, 限定提供商的租户请求 100% 500**: `_handle()` 中租户的
  「提供商限定」检查读取 `provider`, 而其赋值在该检查之后, 触发 `UnboundLocalError`。
  未限定提供商的租户因短路求值侥幸逃过。现将提供商解析前移到租户检查之前。
- **响应缓存跨租户串数据**: 缓存键仅由 `(method, path, body)` 构成, 不同租户发出相同
  提问会命中同一份缓存, 直接读到他人对话内容。现缓存键加入「租户 + 凭证 + 提供商」维度
  (`cache.make_key` 新增 `scope` 参数, 内存缓存与 SQLite 共享缓存同步修改)。
- **管理接口在网络内匿名可读**: 未配置主网关 Key 时 `_authorize()` 对未带凭证的请求
  返回 full 权限, 而监听地址默认 `0.0.0.0`, 局域网内任何人可读取 `/relay/report`
  (含全部 Key 名称 / base_url / 状态) 与运行统计。现匿名请求标记为 `anonymous`,
  管理接口一律拒绝; 代理接口保持开放, 不影响现有客户端。
- **流式响应被误判为流结束, 长思考模型返回空流**: 原实现在 `asyncio.wait_for(gen.__anext__(), 15)`
  超时后发送心跳并继续循环, 但 `wait_for` 超时会取消 `__anext__` 并关闭异步生成器,
  下一次调用抛 `StopAsyncIteration` 直接 `break`。o1 / deepseek-r1 等首 token 前思考
  超过 15 秒的场景必然中断, 且仍记录为成功。现改为独立读取任务 + 队列等待, 心跳不再
  终止上游流。

#### 安全修复 (P1/P2)

- **租户 Token 越权读取管理接口**: 租户 Token 被赋予 `full` 权限, 可访问 `/relay/report`
  等管理端点。现签发 `permission: proxy`, 仅允许代理调用。
- **一处开关操作导致密钥明文落盘**: `/api/gateway/toggle` 用 `to_dict()` 而非
  `to_persist_dict()` 写库, 点一次「暂停/开启网关」就把网关 Key / JWT 密钥 /
  Webhook Secret / Telegram Token 以明文写入 SQLite, 破坏「明文不落盘」的安全模型。
- **管理 API 明文回传全部敏感字段**: `/api/settings` 直接返回内存中的明文。
  现统一脱敏(仅首尾各 4 字符, 长度 ≤12 整体打码), 新增 `/api/settings/secret/{field}`
  按需取单个明文; 前端收到的脱敏值原样回传时后端会丢弃, 不会把掩码写入配置。
- **附加网关密钥被一次保存清空**: 后端 GET 只返回 `key_masked` 并删除 `key`,
  前端把整个对象回传 PUT, 后端按空串加密后被过滤, 结果点一下「启用/停用」即清空
  全部附加密钥。现回传时按 `id` / `key_masked` 复用库中旧密文。
- **配置导出/导入不对称**: 导出的是密文, 导入按明文处理 —— 换机后上游 Key 全部解密失败
  变为空, 而旧租户 Token 以密文形式仍可鉴权。现导出为明文并标注
  `format: intergate-config/2`; 旧格式密文无法解密时跳过并在 `skipped` 中报告,
  不再静默写入空值。导出同时补齐附加密钥 / 模型开关 / 价格覆盖的还原。

#### Bug 修复

- **控制台"无法连接后端"**: i18n 英文词条中遗留连续双逗号导致主脚本块整体解析失败——页面可渲染但所有 API 请求/事件绑定失效。移除多余逗号, 并经 esprima 对线上脚本做语法校验确认修复。
- **一条非法日志丢弃整批写库**: 批量写用单个 `try` 包住三类操作, 且 `model` 列
  `NOT NULL` 而无 model 的请求(如 `/v1/models`)写入 `None`, 一条记录违反约束就导致
  同批次的请求日志、日统计、Key 状态写回全部丢弃。现三类写独立提交, 整批失败时
  降级逐条重试, 只丢弃真正非法的单条。
- **在途请求成功覆盖管理动作**: `record_success()` 无条件将 Key 置为 ACTIVE,
  管理员手动停用或额度耗尽后, 一条并发中的成功请求即可将其复活。现仅
  `ERROR`(运行时冷却)可被成功请求解除。
- **自适应 TPM 限流失效**: 记账用 `tokens // (limit//60)` 的「秒当量」, 却与 token 数
  比较, 量纲不一致 —— 实测连续 20 万 token 一次未拦。现统一按 token 记账。
- **AIMD 降档按请求数触发**: 单位修正后限流真正生效, 即暴露窗口饱和期间每个请求都会
  触发一次乘性下调, 35 个超限请求即可把上限从 10 万压到 339(下限)。现降档加入 60 秒冷却,
  按「拥塞事件」而非「请求数」触发。
- **转发丢失查询串**: 路由只取 path, `?alt=sse`、`?api-version=` 等参数被静默丢弃
  (`_join_base_and_path` 中的 query 处理实为死代码)。现查询串参与转发。
- **Anthropic 上游鉴权头错误**: 统一写入 `Authorization: Bearer`, 而 Anthropic 要求
  `x-api-key`。现按提供商写入, 并在客户端未带时补 `anthropic-version`; 同时不再把
  `anthropic-version` 透传给其它上游, 也不再转发 `x-forwarded-*` / `via` 等链路头。
- **额度耗尽告警风暴**: 额度耗尽后每个后续请求都写一条告警并推送一次 webhook
  (实测 30 次请求 → 29 条告警 + 29 次推送)。现按 (类型, Key) 每自然日只告警一次。

#### 兼容性说明

- **行为变更**: 未配置网关 Key 时, 管理接口 `/relay/*` 由「匿名可读」改为 `401`。
  代理接口 `/v1/*` 与健康检查不受影响。依赖匿名抓取 `/relay/metrics` 的监控需补配网关 Key。
- **行为变更**: `/api/settings` 敏感字段改为脱敏返回, 直接读该接口取值的外部脚本需改用
  `/api/settings/secret/{field}`。
- **数据兼容**: 旧版配置导出文件仍可导入, 但其中跨机不可解密的 Key/Token 会被跳过
  并计入 `skipped`。

### v1.1.2 (2026-08-29)

> 安全加固 + 多租户 + 可观测性大更新: 修复 P0 安全短板, 重构敏感字段落盘,
> 新增多租户 Token 额度体系、后台健康巡检、跨 Worker 共享状态、SSE 保活、
> 失败审计、Telegram 推送、配置导入导出、国际化等。

#### 安全加固 (P0)
- **管理台密码加盐哈希**: 明文改为 PBKDF2-SHA256 加盐哈希存储, 旧明文首次登录自动迁移; 比对用 `hmac.compare_digest` 防时序攻击。
- **敏感字段落盘 AES 加密**: 网关 Key、附加网关密钥、Webhook Secret、Telegram Bot Token、JWT 密钥落盘时统一 AES-256-GCM 加密(`enc$` 前缀), 内存保留明文供热路径比对, 明文不再落盘。

#### 安全修复(多租户)
- **Token 轮换后旧 Token 仍可鉴权(P0)**: `update()` 轮换 Token 时误删新 hash 而残留旧明文 hash, 旧 Token 在轮换后依然有效。现先移除旧明文 hash 再登记新 hash。
- **鉴权索引键类型不一致**: `add()` 误用密文做索引键, 而 `resolve()`/重复检查用 hash(明文), 导致重复明文检测与 O(1) 查找失效(退化为全表解密扫描)。统一为 hash(明文)。
- **删除 Token 索引残留**: `delete()` 现同步清理索引, 防止残留指向已删除的 Token。
- **重启后索引预建**: 加载 Token 时预建 hash 索引, 重启后首次鉴权不再全表解密; 解密失败的 Token 不入索引。
- **重复明文拦截**: 创建/轮换为已存在的明文 Token 时拒绝并返回 400(此前静默成功)。

#### 新功能
- **多租户 Token 体系**: 为每个下游客户端分配独立 `ig-xxx` Token, 支持独立日额度(美元)、请求限流、模型白名单、提供商限定; 按 Token 累计用量并自动拒绝超限; Web 控制台新增「租户Token」管理页。
- **后台健康巡检 + 自动熔断**: 周期探测各上游 Key 连通性, 连续失败自动冷却撤出负载池, 到期自动恢复; 控制台可查看巡检状态/手动触发。
- **JWT 网关鉴权(HS256)**: 可选配置签名密钥, 接受短期 JWT 作为访问凭证, 便于令牌轮换。
- **SSE 心跳保活**: 流式响应 15s 无数据自动发送 `: keepalive` 注释, 防止客户端/中间层误断。
- **失败请求审计**: 可选开启, 记录失败请求体摘要, 便于排查。
- **Telegram 告警推送**: 在 Webhook 之外新增 Telegram Bot 推送通道, 支持测试推送。
- **配置导入/导出**: 一键导出完整配置(设置/Key/价格覆盖/网关密钥/租户/模型开关)为 JSON, 可多端迁移导入。
- **费用导出**: 近 7/30/90 日按 Key 分组的费用 CSV 导出。

#### 架构优化
- **多 Worker 共享状态(可选)**: 新增 SQLite 共享缓存与共享限流计数, 解决多进程下缓存重复、限流额度放大问题; 单进程(默认)仍用内存实现。
- **游标分页**: 日志接口支持 `before_ts` 游标分页, 规避深翻页 OFFSET 全表扫描。
- **上限可配置**: 上游响应体/请求体上限由设置页配置。
- **Prometheus 构建信息指标**: 新增 `intergate_build_info`(版本+实例主机)。

#### 优化 / 修复

### v1.1 (2026-08-25)

> 相对原版的大版本更新：新增多 Worker 并发、模型服务商前缀、自适应用量控制，
> 并完成大规模性能优化与若干 Bug 修复。

#### 新功能

- **多 Worker 并发模式**：网关可多进程并行服务，显著提升并发吞吐；Web 控制台、模型同步在主进程统一管理。
- **模型对外暴露 ID 加服务商前缀**：`/v1/models` 返回的模型 ID 形如 `日日新-deepseek-v4-flash`、`DeepSeek-deepseek-v4-flash`，一眼可知来源服务商；不同服务商 / 不同 `base_url` 的模型彼此隔离，重名模型自动唯一化，互不干扰。
- **调用自动路由到对应服务商**：AI 客户端用带前缀模型名调用时，网关自动反解析并精确路由到提供该模型的那个 Key（相当于点对点隔离）；上游请求自动回写真实模型名，日志/统计/费用均按真实模型记价，不受前缀影响。
- **自适应 TPM 用量控制（AIMD）**：以"乘性减、加性增"动态调整每个 Key 的每分钟 token 上限，冷启动宽松、触发限流后自动降速并逐步收敛。
- **负载均衡轮询升级**：轮询改为按"服务商 + 端点 + 分组"维护独立游标，同名 / 同端点的多个 Key 真正轮流使用，避免一直固定选中第一个；候选 Key 增删或状态变化时自动重建游标。
- **上游连接池可配置**：连接数 / 空闲保持可调节，适配不同上游与并发规模。
- **告警持久化**：额度耗尽、错误率过高等历史告警重启后不再丢失。
- **Web 控制台一键重启**：修改端口 / 并发 / 连接池等需重启生效的设置后，页面提示并可直接一键重启服务，无需手动到终端操作。

#### 性能优化

- **后台批量异步写库**：请求日志、统计、用量写回不阻塞事件循环，攒批一次性落库，高并发下吞吐大幅提升。
- **SQLite 开启 WAL 模式**：读写并发显著改善，多进程下写锁不再相互阻塞，避免繁忙报错。
- **请求体单次解析**：模型名 / 流式标记 / token 估算复用同一份解析结果，降低大请求的 CPU 开销。
- **概览聚合走缓存**：仪表盘、健康检查的今日统计带短时缓存，不再每次全表扫描日志。
- **鉴权热路径零读库**：网关密钥校验走内存缓存，控制台改动即时生效，每请求省去一次数据库读取。
- **限流按 token 加权记账**：高 token 请求一次生效，替代原先逐条叠加。
- **负载均衡延迟记录裁剪优化**：历史样本裁剪避免无效拷贝。

#### Bug 修复

- **Key 管理页"今日用量"跨天显示错误**：昨天用过、今天还没使用时会错误显示昨日残留用量，现按天正确归零。
- **统计落库后读取不到（WAL 快照不可见）**：改用独立写连接，保证读到的始终是已落库的最新数据。
- **Key 自动恢复偶发死锁**：冷却过期的 Key 在自动恢复时不再因重复加锁而卡死。

#### 测试

- 新增完整自动化测试套件：覆盖网关请求流程、缓存、限流、负载均衡、密钥管理等，替代原先仅有的冒烟脚本。
- 适配异步批量写语义，保证行为断言可靠。
- 全量回归：`pytest` 71 项 + 冒烟 62 项全部通过。
